# Task Center 灰度与回退方案（v1）

## 1. 灰度目标

- 新任务中心在不影响旧入口前提下上线。
- 支持按环境和开关逐步放量。

## 2. 开关策略

- `TASK_CENTER_ENABLED=false`：默认关闭，仅保留旧入口。
- `TASK_CENTER_EXECUTION_MODE=simulate|dispatch`：
- `simulate` 仅验证状态机与日志链路。
- `dispatch` 接入真实执行器。

## 3. 发布阶段

### 阶段 0（开发环境）

- 仅开发联调，验证 API 与状态回写。

### 阶段 1（测试环境）

- 使用真实执行器，执行小样本任务。
- 与旧入口结果做一致性对比。

### 阶段 2（灰度生产）

- 小流量使用 task center，旧入口保留可回退。
- 监控失败率、超时率、平均耗时。

### 阶段 3（扩大范围）

- 扩大任务类型与流量比例。
- 满足验收阈值后再讨论旧入口收敛。

## 4. 回退策略

- 任意阶段异常可立即切回旧入口。
- 回退动作：
- 关闭 task center 执行开关。
- 停止 dispatcher/scheduler。
- 保留历史 run 数据用于复盘。

## 5. 回退触发阈值（建议）

- 关键任务失败率 > 5%
- 超时率 > 3%
- 用户可见功能不可用 > 10 分钟

## 6. 数据回退原则

- 新表数据不回滚删除，只做状态封存。
- 旧链路继续作为真执行链路，确保业务可持续。
