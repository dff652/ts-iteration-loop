## 1. 规划原则

- 旧模块保留：现有数据采集/推理/标注入口保持可用，不做破坏性改动。
- 并行建设：新需求通过新增模块和新 API 落地，与旧链路隔离。
- 可灰度切换：通过配置开关控制新入口可见性与流量占比。
- 可回退：任何阶段异常均可回退到旧链路。

---

## 2. 新需求定义

### 需求 A：后台推理任务管理中心

- 将“数据采集 + 推理执行”统一为任务中心能力。
- 覆盖任务全生命周期：创建、执行、监控、取消、重试、归档。
- 支持多种执行方式：手动触发、自动触发、定时调度（Cron）。
- 支持结果管理：查看、筛选、保存、追溯、导出。

### 需求 B：标注双入口能力

- 入口 1：从原始采集数据直接发起人工标注。
- 入口 2：导入推理结果作为预标注，在其基础上人工修订。
- 强制保留来源追踪字段：`source_type`、`source_run_id`、`model_version`、`confidence`。

---

## 3. 目标架构（增量，不替换旧模块）

- 新增路由前缀建议：`/api/v1/task-center/*`。
- 新增数据模型建议：`task_definition`（任务定义，手动/自动/定时、策略配置）、`task_run`（任务实例，每次运行）、`task_step_run`（步骤实例，采集/推理等子步骤）。
- 统一状态机：`pending/running/completed/failed/cancelled/timeout`。
- 结果索引关联：`task_run_id + point_id + model_version`。

---

## 4. 分阶段工作计划

### Phase A（03/03 ~ 03/07）：骨架落地

- 任务中心数据模型与迁移脚本。
- 最小 API：创建、执行、状态、日志、结果查询。
- 任务状态机与错误语义统一。
- 基础回归测试（API + 状态流转）。

### Phase B（03/08 ~ 03/14）：执行与调度

- 手动执行闭环打通。
- 自动触发（最小可用规则）。
- 定时调度（Cron）+ 重入保护 + 失败重试 + 超时终止。
- 运行控制：取消、重试、并发上限、幂等键。

### Phase C（03/15 ~ 03/21）：标注双入口

- 原始数据入口接入标注流程。
- 预标注入口接入（推理结果导入与修订）。
- 来源追踪与回写反查。
- 双链路验收测试。

### Phase D（03/22 ~ 03/28）：灰度与评估

- 新旧并行压测与回归。
- 形成替换评估报告（收益/风险/回退）。
- 决策是否进入“旧入口替换计划”（当前阶段不执行下线）。
- 任务中心能力收敛评估：
  - 核心模式（手动 + 定时）是否覆盖主要业务场景。
  - 高级能力（事件/死信/DAG）是否需要进入下一阶段灰度。

---

## 5. 验收标准（DoD）

- 新旧链路并行可运行，旧链路无行为回归。
- 任务状态口径一致，失败与取消语义明确。
- 推理结果可追溯到任务实例和模型版本。
- 标注结果可追溯到原始数据或预标注来源。
- 核心路径有自动化回归测试覆盖。
- Advanced 能力默认关闭时不影响核心任务闭环。

## 7. 执行矩阵（负责人/工时/风险）

> 说明：负责人以角色标注，避免与人员变动耦合；工时为人天估算。

| 阶段 | 关键任务 | 负责人 | 预计工时 | 风险等级 | 主要风险点 |
| :--- | :--- | :--- | :---: | :---: | :--- |
| Phase A | 任务模型 + migration + 最小 API | 后端负责人 | 4 ~ 6 人天 | 中 | 数据模型边界不清导致后续返工 |
| Phase A | 状态机统一与错误语义收敛 | 后端负责人 | 1 ~ 2 人天 | 中 | 旧状态映射不全引发兼容问题 |
| Phase A | 首批回归测试（API/状态流转） | 测试负责人 | 1 ~ 2 人天 | 低 | 覆盖面不足导致隐性回归 |
| Phase B | 自动/定时调度（Cron、重试、超时） | 后端负责人 | 4 ~ 5 人天 | 高 | 重入、并发与幂等冲突 |
| Phase B | 运行控制（取消、重试、并发上限） | 后端负责人 | 2 ~ 3 人天 | 中 | 取消语义不一致导致任务悬挂 |
| Phase C | 标注双入口接入与来源追踪 | 标注模块负责人 | 4 ~ 6 人天 | 中 | 标注来源字段缺失影响追溯 |
| Phase C | 预标注导入与人工修订回写 | 标注模块负责人 | 2 ~ 3 人天 | 中 | 回写关联错误导致数据污染 |
| Phase D | 新旧并行压测与灰度验证 | 测试负责人 | 2 ~ 3 人天 | 中 | 环境差异导致结果不稳定 |
| Phase D | 替换评估与回退预案文档 | 架构负责人 | 1 ~ 2 人天 | 低 | 评估维度不全导致决策偏差 |

### 风险分级说明

- 低：可在单模块内快速修复，不影响主链路发布。
- 中：可能影响一条核心链路，需要跨模块协同修复。
- 高：可能影响调度稳定性或数据一致性，需预设回退方案。
